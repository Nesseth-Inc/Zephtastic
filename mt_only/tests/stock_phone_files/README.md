# Local PhoneAPI files

The XModem and FileInfo fixture compares the pinned Meshtastic implementation at `8e6a88d06f44cad26f1e8d7cd402939ccacb9b4c` with the production Companion, transfer state machine and range-log filesystem owner. Run `python3 mt_only/tests/stock_phone_files/run.py --stock /path/to/meshtastic` with the pinned commit available locally.

The stock filesystem compile gate covers nRF52 and ESP32. On ZT the manifest exposes `/static/rangetest.csv` when a mounted application filesystem supplies the range-test log. The USB or encrypted BLE configuration handshake grants local access under normal console and management policy. The range logger and transfer use the same file owner. Downloads use a stable reader, and successful EOT commits an upload by renaming its synced staging file. The fixture exercises retransmissions, timeout, disconnect, truncation, transfer contention and preservation of the prior file on failure. The stock board profiles use NVS for private settings. An accessory image with `files.conf` requires a separately mounted filesystem at the configured log directory.


With `--public-files`, the firmware maps the existing dedicated `/public` directory to the virtual `/static/` tree. With `--satellite-history` as well, it uses `/zt-history/public` on the dedicated volume instead. Only this subtree is exposed. Both transports enumerate up to 64 regular files across three directory levels with separate cursors. Hidden paths, traversal, staging files and the private history directory are excluded. An upload becomes visible after sync, close and rename. An interrupted upload preserves the previous version. Admin deletion uses the same serialized file owner. The tests exercise both physical root mappings, enumeration under queue pressure, root escapes, directory deletion, cancellation and nested file transfers.
