# Signed Wi-Fi update tests

Run `python3 mt_only/tests/stock_signed_ota/run.py` with Python cryptography, a C++20 compiler and OpenSSL development files. On macOS, set `OPENSSL_PREFIX` to the OpenSSL installation prefix. The fixture creates a temporary P-256 signing key in memory and runs against an in-memory NOR model.

The authorized XIAO Wi-Fi updater sends two UDP datagrams each second during its existing OTA window. Android accepts the stock loader’s device-name/version string and dials TCP port 3232 at its source address. Apple v2.7.21 accepts a datagram beginning with `MeshtasticOTA` and dials the complete source endpoint. The updater sends the Android beacon from an ephemeral UDP port and the Apple beacon from a separate socket on the station’s TCP port. Apple cancels each UDP flow after the first datagram, including when its prefix check fails. Separate source ports allow both clients to discover the station regardless of beacon order. If that UDP bind fails, the updater still sends the Android datagram and serves TCP for clients using an explicit host. [Android validator](https://github.com/meshtastic/Meshtastic-Android/blob/03ad76189538bc0e603dac6ba828b8521f0207db/feature/firmware/src/nonWebMain/kotlin/org/meshtastic/feature/firmware/ota/WifiOtaDiscovery.kt#L91-L99) · [Apple discovery](https://github.com/meshtastic/Meshtastic-Apple/blob/4ea817379c4d70075c3c5b8cc0cecee7938a23bd/Meshtastic/Views/Settings/Firmware/ESP32%20OTA/WiFi/ESP32WifiOTAViewModel.swift#L261-L291)

The discovery fixture uses ephemeral IPv4 loopback ports. It receives both production datagrams, opens a TCP connection using the Apple datagram’s source tuple, and checks fallback after a conflicting UDP bind. Separate socket-pair tests exercise the update command, progressive ACKs, final signature verification and hash rejection. An actual radio or LAN broadcast is unnecessary for these tests.

On macOS, `python3 mt_only/tests/stock_signed_ota/apple_discovery.py PATH_TO_MESHTASTIC_APPLE` compiles the pinned Apple client from a local checkout and uses native Network.framework on IPv4 loopback. It exercises both arrival orders with shared and separate UDP source ports and completes the stock Swift TCP transfer where discovery succeeds. The fixture temporarily uses UDP 3232 on localhost.
