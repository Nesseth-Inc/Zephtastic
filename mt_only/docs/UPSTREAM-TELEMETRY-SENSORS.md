# Telemetry sensors on the T096 and XIAO S3

The pinned upstream Telemetry/Sensor directory contains 46 C++ translation units. Three provide shared or placeholder behavior, including the BME680 estimator shown with its sensor below. A translation unit appearing in the donor tree does not establish that either board has the part fitted. This inventory traces originating local measurements. Phone decoding and forwarding also support fields a local sensor cannot currently produce. [Pinned donor source](https://github.com/meshtastic/firmware/tree/8e6a88d06f44cad26f1e8d7cd402939ccacb9b4c/src/modules/Telemetry/Sensor)

The Heltec T096 variant defines an onboard battery divider and UC6580 GNSS. ZT's board DTS exposes the divider on SAADC channel 1 and the GNSS control pins. Its shared I²C devicetree list explicitly probes optional chips. The stock XIAO S3 variant declares `BATTERY_PIN=-1`, exposes I²C and documents the external L76K. The ZT XIAO radio overlay disables i2c0 in its default configuration. The two production board definitions provide no evidence of a fitted BME680, pulse oximeter, particle sensor or other accessory in the table. Physical population and calibration remain unverified. [T096 variant](https://github.com/meshtastic/firmware/blob/8e6a88d06f44cad26f1e8d7cd402939ccacb9b4c/variants/nrf52840/heltec_mesh_node_t096/variant.h) · [XIAO variant](https://github.com/meshtastic/firmware/blob/8e6a88d06f44cad26f1e8d7cd402939ccacb9b4c/variants/esp32s3/seeed_xiao_s3/variant.h) · [ZT T096 board](../../zephcore/boards/nrf52840/heltec_t096/heltec_t096_nrf52840.dts) · [Common sensor candidates](../../zephcore/boards/common/sensors-i2c.dtsi) · [XIAO overlay](../boards/xiao.overlay)

The optional `--xiao-l76k` build fits the Seeed XIAO ESP32-S3 and Wio-SX1262 pin map. Use it only with the L76K expansion board's RESET connection isolated from the Wio SPI pins, as specified by the stock variant. It reads 9,600-baud NMEA on UART0 (RX GPIO44, TX GPIO43), drives active-low standby on GPIO1, and keeps the phone console on USB Serial/JTAG. The application issues no receiver commands. It uses the same fix, freshness, UTC, fixed-position and disabled-mode handling as the T096. The ordinary XIAO firmware advertises no GNSS. Native tests cover parsed fixes, standby polarity and driver failure ordering. Receiver startup, wiring, power draw, and signal acquisition need a fitted accessory. [Stock variant](https://github.com/meshtastic/firmware/blob/8e6a88d06f44cad26f1e8d7cd402939ccacb9b4c/variants/esp32s3/seeed_xiao_s3/variant.h) · [XIAO wiring](../boards/xiao-l76k.overlay) · [Pinned standby test](../tests/stock_l76k/run.py)

`--xiao-l76k-managed` selects the same wiring and enables the L76K's receiver setup after live GNSS is requested. It checks the donor's common UART rates twice (9,600, 115,200, 38,400), then checks 4,800, 57,600 and 9,600. A CAS software-version reply selects the L76K settings for GPS/GLONASS/BeiDou, GGA/RMC output and vehicle mode. The firmware checks for the other known ATGM33xx hardware replies before configuring. An absent or unrecognized receiver falls back to passive 9,600-baud NMEA, and fixed-position or disabled mode cancels acquisition. The worker retains the detected rate while running and probes again after reboot. This profile uses only the L76K version queries and volatile setup commands. Neither profile drives the conflicting reset connection. [Stock probe and setup](https://github.com/meshtastic/firmware/blob/8e6a88d06f44cad26f1e8d7cd402939ccacb9b4c/src/gps/GPS.cpp) · [Adapter and failure boundaries](../src/gnss/L76kSetup.h)



## Local producers

Each name in the first column is the exact filename stem of a pinned `.cpp`. “Channel binding” means that a compatible Zephyr driver must implement the indicated channel, its board overlay must select the device and the module must be enabled. It does not establish device-specific timing or calibration equivalence.

| Donor files | ZT measurement path and qualification |

| AHT10 | An explicitly declared AHT10/AHT20 returns six-byte T/RH measurements and fills only missing fields. [AHT and barometer comparisons](../tests/stock_barometers) |
| SHTXXSensor | One SHT worker selects among the five stock-reachable protocol/address combinations on a declared bus, including serial-verified SHT2x. The selected SHT3x or SHT4x accepts all three USB accuracy settings. The native path also implements repeatability on SHT3x/4x. The tests compare native channel conversion and pinned stock float values. [SHT selection, measurements and limits](../tests/stock_sht) |

| BMP085Sensor, BMP3XXSensor, DPS310Sensor | Explicit BMP085/BMP180, BMP388/BMP390 and DPS310 workers reproduce the stock oversampling, compensation and corresponding T/P wire fields. A BMP3xx reading clears RH. The linked fixtures exercise both boards and the native tests compare the SDK and stock algorithms. [Barometer qualification and headroom](../tests/stock_barometers) |

| TelemetrySensor, nullSensor | Common lifecycle and placeholder translation units. Neither describes a physical sensor. |
