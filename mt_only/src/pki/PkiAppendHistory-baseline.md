# Read-only append baseline access

`PkiAppendHistory::reconstructBaseline()` is a cold, read-only decoder for the 4,096-byte immutable root. It takes the current validated local node/public key from the caller, checks the fixed geometry, full root CRC and commit, canonical 1,944-byte v2 ledger snapshot, generation/seal, zero padding, and identity binding. It does not load settings or require the old NVS ledger/anchor. The returned `AppendAnchor` is reconstructed from that root's validated fields; it is not an independent authenticated selector.

Output is staged until every root read and validation succeeds, so read errors, torn data, or mismatches leave both caller outputs unchanged. `PkiLedger::loadValidatedAppendBaseline()` can place that validated snapshot and anchor into a fresh RAM ledger view without reading or writing settings. The anchored view rejects the ordinary ledger mutation APIs. Passing it to the existing `PkiAppendHistory::open()` revalidates the root and replays the full 2,624-cell event region, deriving effective contacts without dropping later Add/Revoke/TX/RX events. This proposal does not rewire boot or storage migration.

The original `readBaselineChunk(offset, out, size)` seam remains available after `open()`. It bounds each transfer to 64 bytes and compares each root chunk against the currently loaded `PkiLedger` snapshot. It performs no writes or repairs.

The accessor bounds each transfer to 64 bytes, checks the copied root chunk against the already validated `PkiLedger` snapshot, and stages the chunk before publishing it to `out`. Invalid state, range, storage errors, and mismatches leave that call's output unchanged. A caller assembling the full baseline must discard its destination if any chunk fails. Reading does not write settings or append storage; the append object remains open with post-baseline Add/Revoke/TX/RX events folded, so later lifecycle events are not discarded.

This is a component seam for a future migration. The root format contains no nonce-authority binding; the caller must separately preserve/validate the currently selected nonce records before any runtime use. CRCs detect accidental corruption but do not authenticate the root against a forged whole-root replacement. This work does not alter identity or nonce records, select a compact store, or prove an integrated storage migration.
